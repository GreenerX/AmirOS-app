# Controlled beta feature contract

The Control Center supplies feature assignments only through the authenticated
device entitlement response. They are account-scoped, server-authorized, and
audited. The Control Center does not receive the content generated by any of
these features.

## Feature IDs

| ID | Default | Local-app behavior when explicitly disabled |
| --- | --- | --- |
| `deleted-message-archive` | enabled | Hide the archive setting and do not capture or reveal deleted-message records. Existing local archive data remains local and can only be removed by the owner. |
| `relationship-suggestions` | enabled | Do not create or display inferred relationship suggestions. Existing canonical facts remain unchanged. |
| `reply-suggestions` | enabled | Do not offer generated reply suggestions or their feedback flow. Manual messaging remains available. |

Defaults preserve existing beta behavior. For an active paired device, a
per-account assignment is authoritative. An unmanaged, unpaired, or pending
copy keeps its local behavior; the Control Center must not become an accidental
new access gate for these optional features.

The local app must treat an explicit `enabled: false` as the authoritative
control. Missing definitions or an unavailable Control Center must not make a
managed copy invent a new restriction; ordinary entitlement access and the
release decision remain separate.
